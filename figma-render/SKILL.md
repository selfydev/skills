# Figma render

Figma screens built by improvised Plugin API scripts come out misplaced, overlapping and clipped, because the order of API calls decides the result. Paper does not have this problem because its layout engine places everything from HTML and flexbox. This skill gives Figma the same property: you describe the layout, one tested renderer builds it.

## The rule

Auto-layout on every design, including the screen root. The only node allowed outside its parent's layout is one the spec marks `abs`. Never create or move Figma nodes with a hand-written `figma_execute` script when a spec can describe them.

## Prerequisites

- Figma Desktop open on the target file, Desktop Bridge plugin running, figma-console MCP connected (`figma_get_status`).
- The Figma file's name, exactly as it shows in the title bar. Every payload below is built with `--file "<file name>"`, because the Bridge runs a payload in whichever file it is attached to, which is not always the one you mean. A payload built with `--file` checks `figma.root.name` first and throws, touching nothing, when the open file is a different one.
- The file has, locally: the variables the spec names (slash names, `color/surface/canvas`, map to dot names in specs, `color.surface.canvas`), the text styles it names, and the components it instances. The renderer stops and lists anything missing before it builds.

## Workflow for one screen or component

The CLI is `node ~/.claude/skills/figma-render/bin/figma-render.mjs`, shortened to `figma-render` below.

1. Write the spec as JSON in the project's repo, for example `figma/screens/settings-ar.json`.
2. `figma-render validate <spec> --manifest <icons manifest> --tokens .figma-render/tokens.plan.json` until it prints `spec is valid`. `--tokens` (the plan `figma-render tokens` writes) checks every collection and mode a spec pins against the file's collections; without it only their shape is checked.
3. `figma-render render <spec> --manifest <icons manifest> --tokens .figma-render/tokens.plan.json --file "<file name>"`. It prints the plan and payload paths.
4. Read the payload file and pass its entire contents as the code for `figma_execute`, with `timeout: 30000` (the default of 5000ms is too short; a run can load every page and font). The result is `{ rootId, name, hash, nodes }`.
5. `figma-render snapshot <rootId> --file "<file name>"`, pass that payload to `figma_execute` with `timeout: 30000`, and save the returned JSON as `.figma-render/<slug>.snapshot.json`.
6. `figma-render gate .figma-render/<slug>.snapshot.json .figma-render/<slug>.plan.json`.
7. Capture the root with `figma_capture_screenshot` at scale 2 and look at it yourself. A clean gate does not replace looking.
8. Report the gate table and what the screenshot shows. Done means zero `fail` lines and a screenshot you have reviewed.

If a fix does not reduce the number of failing checks, stop and show the table instead of looping.

## Spec reference

Root, one of:
- Screen: `screen` (name), `size` [w, h] (numbers or size tokens; h may be `hug` for notes and annotation frames), `direction` `ltr` or `rtl`, `lang`, `fill`, `textColor`, `gap`, `pad`, `align`, `justify`, `modes` { collection name: mode name } to pin the frame to a theme (for example `{ "Semantic": "Dark" }`), `children`.
- Component: `component` (name), `textColor`, `direction`, `textProps` { propertyName: textLayerName }, `boolProps`, `swapProps`, `setLayout`, `variants` [ { `props` { Name: Value }, plus stack keys } ].
  - `boolProps` { "Has icon": { `layer`: "Leading", `default`: true } }: a BOOLEAN property bound to the visibility of every layer with that name in every variant (`default` is true when left out). Every variant must have the layer, unless the prop sets `partial: true` (then at least one must, and the property binds the variants that have it; use it for a variant that replaces the layer, such as a Loading state that shows a loader instead of the icon).
  - `swapProps` { "Leading icon": { `layer`: "Leading", `preferred`: ["Icon"] } } (`partial: true` works as for `boolProps`): an INSTANCE_SWAP property bound to that instance layer in every variant. Figma keeps one component per instance swap property for the whole set (binding a layer swaps it to the default, and swapping any bound layer moves every one), so every bound layer must show the same component, and that component is the default; the validator stops a spec whose variants differ. For sizes that need different icon sizes, default the swap to one size (such as `Icon` Size=16), resize the slot per variant (`w` and `h` on the instance, 12 in Small, 20 in Large), and draw the swapped-in component so its glyph fills its frame (`w`/`h` `fill`), so the glyph scales with the slot; a swapped instance keeps the slot's size. Stroke weights do not scale with the resize, so a stroke drawn for 16 is thicker, relatively, at 12 and thinner at 20. `preferred` lists component or set names, which must exist in the file, as the property's preferred values. Render those sets first.
  - `setLayout` lays the set out. A grid: { `rows`: "Name", `columns`: "Size", `order`: { "Size": ["10", "12", "16", "20"] }, `gap`, `pad` } puts each variant in the row and column its props name (an axis can be a list of props, such as `["Variant", "Size"]`); values follow `order`, or first appearance in the spec; a missing combination leaves an empty cell. A wrap: { `wrap`: true, `width`: 640, `gap`, `pad` } is a row that wraps at that fixed width, in spec order. `gap` and `pad` are tokens or numbers (default 24, raw). `fill` (a colour token, a hex or a gradient, raw ones reported) paints the set frame as a documentation backdrop, for sets whose variants are light on transparent, such as a status bar for dark screens. Without `setLayout` the set is one hugging row.

Nodes, exactly one kind each:
- `stack` (name): `dir` `row` or `col` (required), `gap`, `pad`, `align` start, center, end, baseline, `justify` start, center, end, between (Figma ignores the gap under between, so a stack that hugs its main axis with between and a gap packs its children with none; validate prints a warning and the gate warns under auto-layout; put the spacing in a child's padding instead), `wrap` true on rows, `fill`, `stroke` { color, width, `dash` [dash, gap] in px for a dashed stroke, `align` inside (default), center or outside, as for a focus ring that must not cover content }, `radius` (one value, or four corners [top-left, top-right, bottom-right, bottom-left]), `clip`, `blur` (background blur radius in px, for glass; pair it with a translucent fill such as `#ffffff33`), `shadow` and `innerShadow` (lists of { `x`, `y`, `blur`, `spread`, `color` }, each number a token or a number, missing ones 0, `color` a colour token or hex; drawn as DROP_SHADOW / INNER_SHADOW effects with every token bound, and a drop shadow never shows through the node, as in CSS), `modes` { collection name: mode name } (see Modes below), `opacity` (a number from 0 to 1, raw and reported, or an opacity token such as `opacity.dimmed`, bound; for content dimmed behind a popover; the snapshot records it with its variable's name and value, and `spec-parity` checks that the opacity equals the variable's value / 100 and fails a variable holding a fraction), `children`.
- `text` (the characters): `style` (required text style name), `color`, `align` start, center, end, `truncate: true` (one line ending in an ellipsis instead of wrapping; needs `w` fill or a number), `name`.
- `instance` (component name): `props` { Name: value } using the names Code Connect reads (a BOOLEAN property takes true or false; an INSTANCE_SWAP property takes { `instance`: "Icon", `props`: { "Name": "back", "Size": "16" } }, which picks that set's variant and sets any other props on the swapped-in layer; every value is read back, and one Figma ignored stops the render), `tint` (a colour token: binds every painted vector inside the instance to it, as an override that runs after bool and swap props bind, for an Icon on an ink button; Figma drops a main component's nested override when a consumer swaps the instance, so a swapped-in icon falls back to its own colour), `icon` (a name in the mirroring manifest), `modes` { collection: mode } (overrides the mode its main component pins, as for a Secondary Icon button whose glyph should read one tone lighter; the snapshot records only the modes an instance pins differently from its main; a pin equal to the main's own pin is a no-op Figma cannot tell apart, so the runtime skips it, stamps it and the snapshot still reports it), `key` (a published component key, to import a library component such as Apple's status bar) and `set: true` when the key is a component set's. `expose: true` (component specs only) exposes the nested instance, so a consumer of the set can set its props without the set repeating them as its own properties; it runs after the set's bool and swap props bind, and spec-parity checks it. `exposed` { layer name: { prop: value } } is the consumer side: it sets the props (variant, text, bool) of the exposed instance with that layer name, for example `{ "instance": "Tray", "exposed": { "Tag": { "Label": "01 paused" } } }`; every value is read back, and a layer that is not exposed stops the render. Exposed instances are targeted by layer name, first match wins, so give each exposed instance in a component a unique layer name. A swap value's `props`, and an `exposed` layer's props, may themselves hold swap values, to any depth: `{ "Action": { "instance": "Button", "props": { "Variant": "Secondary", "Icon": { "instance": "Icon", "props": { "Name": "share" } } } } }` swaps a Button into the Action slot and its Icon to share, and `"exposed": { "Action": { "Label": "Share", "Icon": { "instance": "Icon", "props": { "Name": "share" } } } }` does the same on an exposed Button. Plain values are set first, then the nested swaps; each lands on the layer bound to that swap property, and every value is read back. A swap value may also carry `exposed` { layer: props }, which sets the swapped-in component's own exposed instances after its props and nested swaps, for a container whose Content slot is swapped for a component with exposed rows: `{ "Content": { "instance": "List group", "props": { "Count": "2" }, "exposed": { "Row 1": { "Title": "Booked flight" } } } }`.
- `shape` (name): `kind` rect, ellipse or svg, `size` [w, h] (numbers or size tokens), `fill` (rect and ellipse only), `svg` (markup; carries its own colour unless `tint` names a colour token, which binds every painted fill and stroke in it to that variable and keeps each paint's opacity, so icons follow the theme).

Every node: `w` and `h` are `fill`, `hug`, a number, or a size token such as `size.control.md` that binds the width or height variable (text height is always hug, and text width is never a token), `abs` { `start` or `end`, `top` } takes the node out of flow, `name` overrides the layer name.

Values: a token name (`space.inset.md`), a number (raw, rounded, reported by the gate), or a hex colour (`#ffffff`, raw, reported). A `fill`, a stroke `color` or a text `color` can also be a gradient: `{ type: 'linear', angle, stops: [[0, '#hex'], [1, '#hex']] }` (angle 0 runs left to right, 90 top to bottom) or `{ type: 'radial', cx, cy, r, stops }` (fractions of the node). A stop's colour may be a colour token instead of a hex (`[0.36, 'color.shimmer.head']`): the stop binds its variable through an alias (`ColorStop.boundVariables.color`), so the gradient follows the mode, alpha included. A gradient is bound only when every stop is; one with any hex stop is raw and reported (the snapshot lists it as an unbound fill, stamped raw). An svg shape's own gradients (from its markup) take `stopTints`, a list of colour tokens: stop i of every gradient inside the svg binds token i, keeping positions and geometry; a gradient with a different stop count stops the render. An image fill is `{ type: 'image', image: '<name>', scaleMode }`: upload the image once (Figma MCP `upload_assets`), then store its hash on the file as root plugin data `figmaRender.image.<name>`. Screen `modes` can also name a collection a library component binds (Apple's `Colors`: Light, Dark). `pad` is one value or { block, inline, top, bottom, start, end }.

### Modes

Any stack, any component variant and the screen root can pin a collection's mode with `modes`, for example `{ "Icon tone": "On inverse" }`. The runtime calls `setExplicitVariableModeForCollection` on that node, so every variable bound inside it, including inside instances, resolves in that mode, unless a nearer node pins another. A collection left unpinned follows the nearest ancestor that pins it, or the collection's default mode. Use it for colour that must follow the surface: a variant with an ink fill pins `Icon tone: On inverse`, and an Icon whose glyph binds `icon.current` turns white inside it, even after a consumer swaps the icon (a swap can drop a main component's `tint` override, but never an ancestor's mode). Pin every variant of a component that paints its own surface, including the default one, so a mode set further out cannot leak in; never pin the Icon itself, or it stops inheriting. Every collection and mode must exist before render starts (it stops and names the one missing), and `--tokens` catches them at validate time. A screen that instances a library component may also pin that library's collections (Apple's `Colors`: Light, Dark), which the token plan cannot know. The snapshot records each node's explicit modes by collection and mode name (instances excepted: they show their main component's), and `spec-parity` fails when one is missing, different or unexpected.

## The gate

Nine checks, each pass, warn or fail with the node named: `auto-layout`, `positioning`, `overlap`, `overflow`, `clipped-text`, `half-pixels`, `default-names`, `unbound-values`, `spec-parity`. Siblings stacked by a negative gap (a stack with `gap` set to a negative token, such as overlapped avatars) warn on `overlap` instead of failing. A layer hidden by a bool prop (off by default) is not laid out, so its geometry is skipped by `overlap`, `overflow` and `half-pixels`; its sizing is read from what Figma persists (`layoutAlign`, `layoutGrow`, and a text's `textAutoResize`), because live Figma reads a hidden layer that fills its parent, or a hidden text that hugs, as FIXED. Raw values the spec chose on purpose warn; unbound values that should be tokens fail. A shadow colour counts like a fill (`effects`), and a grid set's gaps like spacing (`gridRowGap`, `gridColumnGap`). `spec-parity` fails if the Figma tree no longer matches the spec, which catches hand edits; it also checks a set's `setLayout` (grid size and each variant's cell, or wrap width), the layers bool and swap props bind, the set's BOOLEAN and INSTANCE_SWAP properties, the effect types of a stack with a shadow, whether each instance is exposed, and each node's explicit modes (a snapshot taken before modes were recorded skips that check).

## Tokens

Before building any spec in a new file, import its design tokens first, so the variables and text styles the spec binds to already exist.

1. `figma-render tokens <resolver.json> --file "<file name>"`. It prints each collection's variable count, their modes, the text style count, the payload size and the skipped list.
2. Read the payload file (`<out>/tokens.import.js`) and pass its entire contents as the code for `figma_execute`, with `timeout: 30000`. The result is the import report.
3. Re-run this step after any change to the tokens; it updates the variables and text styles it made in place by name, so bindings a spec already made survive. It never writes to a collection or text style it did not make unless you pass `--adopt`.

Two collections come out of a resolver: `Primitives`, hidden from pickers and publishing, holds the raw values; `Semantic`, with one mode per theme, holds the names specs bind to, plus component tokens under `component/`. A spec's token values (`color.surface.canvas`, `space.inset.md`) are always semantic dot names, never primitives.

A resolver can add collections of its own, one per modifier marked `"$extensions": { "com.figma": { "collection": "Icon tone" } }`, for a colour that follows its surface rather than the theme. The set marked with the same collection holds its tokens (`"iconTone": { "sources": [...], "$extensions": { "com.figma": { "collection": "Icon tone" } } }`), and each of the modifier's contexts becomes a mode, named exactly as written (`Default`, `On inverse`), default context first. Each context overrides the set's tokens with an alias to a Semantic token, so a variable in the collection resolves through the Semantic mode too, and Light and Dark still work. Only that modifier may override those tokens, and it may override nothing else; the theme modifier cannot be marked; `Primitives` and `Semantic` are reserved names; a marked set with no marked modifier, or the reverse, stops the plan. Specs bind the variable by its dot name (`icon.current`) and pick its mode with `modes` on a stack or variant (see Modes).

What each variable and style carries:
- Scopes come from naming rules (`src/token-values.mjs` `SCOPE_RULES`, first match wins). Colours go by what the role paints: `*/background*`, `*Bg`, `color/surface|fill/*` get frame and shape fills; `*/text*`, `*Fg` the text fill; `*/border*`, `ring/*`, `*/divider*` the stroke colour; `color/icon/*`, `*/icon`, `*/glyph*` shape fills and strokes; `*Dot`, `*/dot/*` shape fills; `shadow/*` the effect colour. A colour named none of these gets `ALL_FILLS` + `STROKE_COLOR`. A token or group `$extensions["com.figma"].scopes` replaces the rule (use `[]` to hide it from pickers).
- `$description` becomes the variable's description, and a typography token's `$description` the text style's. A typography token with no `$description` leaves the style's description as it is, so one typed in Figma survives.
- Code syntax: `WEB` is `var(--kebab-path)`. A token's own `$extensions["com.figma"].codeSyntax` (`{ "iOS": "...", "ANDROID": "..." }`) adds or replaces platforms; it is never inherited from a group. A resolver-level `$extensions["com.figma"].codeSyntax` rule such as `{ "iOS": { "namespace": "Acme", "categories": { "type": "Font" } } }` derives `Acme.Color.textPrimary` for every Semantic variable (not Primitives); a first word starting with a digit moves its digits to the end (`radius.2xl` → `Acme.Radius.xl2`), and a name that still is not a valid identifier stops the plan and asks for the token's own code syntax.
- A collection is hidden from publishing when every variable in it is.
- A `number` token whose only scope is `OPACITY` is written as a percentage (0.32 becomes 32), because Figma reads a variable bound to layer opacity as 0–100. Its value must be a fraction from 0 to 1.

Flags:
- `--file "<file name>"`: pins the payload to that file (see Prerequisites). Always pass it.
- `abs` overlays: `top` or `bottom` (one), and `start`, `end` or both (both stretches the overlay between them). Figma constraints keep it in place as the frame resizes: bottom is MAX, both sides STRETCH. Use bottom + both sides for a scroll fade. `top` and `bottom` together, with `start` and `end`, make a full cover stretched on both axes (STRETCH both ways), for a Modal backdrop behind a centred modal.
- Stack `dir: "grid"` with `columns: n`: equal columns, children placed in reading order, every row hugging its tallest child, `gap` on both axes. Each child takes `w` and `h` "fill" (it fills its cell). Use it for tiles that must share width and height: a row of fill children cannot, because Figma shares fill width by content and stroke width.
- Instance `slots` { "Body": [children] } (or { "Body": { "dir": "row", "children": [...] } }; add `"h": "fill"` to that object form to fill the slot to its instance's height, for a Card stretched by its grid row whose action must sit at the bottom; only the shorter card in a row should fill, since the row's height comes from the card that hugs): fills a library container's Figma slots (Modal Body, App chrome Content). The slot's default content is removed and the children are built inside it; the instance is stamped `figmaRender.slots`, the snapshot records each filled slot with its content, and the gate checks it (auto-layout, overlap, spec-parity) like any stack. A slot the instance does not have stops the render.
- `--library <library.json>` (render): a consumer file that uses a published design system. The manifest maps names to keys: `{ "variables": { "space/gap/md": "<key>" }, "textStyles": { "body/md": "<key>" }, "components": { "Button": { "key": "<key>", "set": true } } }`. Variables and text styles the file does not hold locally are imported by key (`importVariableByKeyAsync`, `importStyleByKeyAsync`), components through the existing key import, and a stack can pin a mode of an imported variable's collection. Only the keys the spec needs go into the plan. A local token or component of the same name wins; one neither local nor in the manifest still stops the render. Harvest the keys in the library file (`variable.key`, `style.key`, `set.key`).
- `--theme <name>` picks which modifier becomes the Semantic collection's modes (default `theme`).
- `--out <dir>` changes where the plan and payload are written (default `.figma-render`).
- `--adopt` lets the importer take over a collection or text style with a planned name that figma-render did not make. Without it the run stops before writing anything and names the item. Only pass it once you have confirmed the hand-made item should become the token-managed one; with it, a mode the plan does not use may also be renamed to a planned mode.
- `--prune` removes variables and text styles that figma-render made and the plan no longer defines, but only ones nothing uses. It needs `--file`, and the CLI exits 2 without it.
- `--force`, with `--prune`, removes stale items even when they are still in use. This unbinds every variable, style and node that points at them, so only pass it after reading `usedBy` and `moved` and moving those bindings yourself.

Reading the report:
- `created` and `updated`: variables and text styles written this run (`updated` means one figma-render already owned matched, whether or not its value changed).
- `renamedModes` `[{ collection, from, to }]`: every mode the importer renamed. On a new collection this is its `Mode 1`. On an existing collection it only happens with `--adopt`; say so when you report the run.
- `extraModes`: modes a collection has that the plan does not use. They are kept, never removed or reordered, and a planned mode missing beside them is added.
- `stale`: items figma-render made that the plan no longer defines, each with `usedBy { variables, textStyles, nodes }`: other variables aliasing it, text styles binding it, and nodes on any page bound to it (paint colours included) or, for a text style, using it.
- `moved` `[{ path, from, to }]`: a stale variable whose DTCG path the plan now puts under another name or collection. Nothing is migrated: rebind what uses `from` to `to`, then prune.
- `removed` and `keptInUse`: with `--prune`, how many stale items were removed, and the stale items kept because something still uses them (with their `usedBy`).
- `skipped`: tokens with no Figma variable type.
- `fontsMissing`: text styles not updated because no listed family loaded in the weight's styles (`styles` lists the names tried), or because the weight has no Figma style name at all (`unsupportedWeight`). The style keeps its old values until that is fixed.

## Honest limits

- The unit tests use a fake `figma` with no layout engine, so geometry (overlap, overflow, half pixels) is proven only by checking live renders in Figma.
- Variables, text styles and components must be local to the file.
- A spec's variable names must be unique in the file: if two local variables share a dot name the spec needs (the same slash name in two collections), render stops and names both collections.
- An svg shape keeps the colours in its markup unless it has a `tint`.
- Grid set tracks hug their content, so a column is as wide as its widest variant and variants sit at the top left of their cell.
- Figma property keys carry a `#id` suffix; specs and the gate use the name before it.
- Re-rendering a component set replaces it, so instances already placed from the old set lose their main component. Render components before the screens that use them, and do not re-render a set that screens already instance.
- Token import never reorders or removes a collection's modes, and library variables (from another file) are not supported; every token must be local to the file.
